# 🎤 カラオケどこ得？ 完全版 v2

出発地点・人数・歌う時間・曜日・利用者・移動手段・ポテト・アルコール飲み放題を入力し、**カラオケ代＋追加料金＋往復移動時間＋交通費**を合わせて「実質円/h」で比較するためのGitHubプロジェクト。

## 今回の「本丸」

### 1. 店舗データ
7チェーンを店舗単位で管理。

- まねきねこ
- ビッグエコー
- BanBan
- ジャンカラ
- カラオケ館
- コート・ダジュール
- 快活CLUB

`collect_official.py` は各公式店舗検索から店舗ページを発見し、JSON-LD/ページ本文から住所・電話・設備等を取得する。チェーンごとにURL構造が違うのでアダプター方式。

### 2. 料金データ
`prices.json` は **店舗 × プラン × 利用者 × 曜日 × 時間帯** で保持。

比較時には、指定時間をカバーするフリータイム/パックと、30分料金×必要コマ数を比較して安い方を採用する。

画像料金表などをOCRで勝手に数値化して確定する処理はしない。`collect_prices.py` が画像料金表を検出した場合は `prices_review.json` に「OCR/手動確認が必要」として残す。これにより誤料金を公開データへ混ぜない。

### 3. ポテト
`options.json` で店舗ごとに管理。

想定ルール：
- `all_you_can_eat` = 食べ放題
- `portion` = 1人前
- `double_for_even` = 偶数人数なら2倍盛り等を注文し、人数で割る
- `unavailable` = 対象なし

**料金が分からないものは0円扱いしない**。比較結果を「暫定」にする。

### 4. アルコール飲み放題
ポテトと同じく店舗別オプション。価格不明なら暫定表示。

### 5. ルート検索
- 徒歩：OSRM
- 車：OSRM（燃料等を仮に20円/kmとして交通費を推定。設定変更可能）
- 公共交通＋徒歩：Google Routes APIをサーバー側に設定可能

GitHub PagesへAPIキーを置かないため、`api.py` を別ホスティングへ置く構成を採用。

Google Routes APIを使う場合はサーバーに `GOOGLE_ROUTES_API_KEY` を設定する。

### 6. 円/h
デフォルトでは、

`(カラオケ料金 + オプション料金 + 往復交通費) ÷ 人数 ÷ ((歌唱時間 + 往復移動時間) / 60)`

で計算。

つまり、2時間歌う店でも往復1時間かかれば「3時間使う遊び」として比較できる。

### 7. 「ほぼ同額だけどメリットが違う」表示
最安との差が10%以内なら注意書きを表示する。今後、設備・ポテト食べ放題・ドリンクバー・移動時間などの差を理由別に自動生成できる構造。

## 現時点の検証済みシード

公式ページで確認した実データを少数入れている。例えばビッグエコー宇治店は学生30分200円/土日祝280円、昼3時間パック平日1120円など、ジャンカラ京都駅前店は学生会員の昼30分平日320円・土日祝460円、昼フリータイム平日1630円など、快活CLUB西院駅前店はカラオケ30分330円・3時間パック1200円などを登録している。

全国全店舗の料金は公式ページごとに構造が違い、料金画像の店舗もあるため、**自動取得できないものを推測で埋めない**方針。

## GitHubでの使い方

1. このフォルダの中身をリポジトリ直下へアップロード
2. `.github/workflows/refresh.yml` が存在することを確認
3. Actions → `Refresh official karaoke data` → `Run workflow`
4. `Deploy Karaoke Dokotoku` が成功すればPagesが更新される

## APIサーバー

```bash
pip install -r requirements.txt
uvicorn api:app --host 0.0.0.0 --port 8000
```

本番ではCORSを自分のPagesドメインだけに絞ること。

## 注意

料金・営業時間・キャンペーンは変更される。公式サイトを一次情報源として定期更新し、`source_url` と `checked_at` を保存する。

スクレイピング時は各公式サイトの利用規約・robots.txt・アクセス制限を尊重すること。
